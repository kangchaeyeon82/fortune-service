# 결과 데이터 구조 (sample_result.json 기준)

최상위: `profile`(입력값), `landing`(Firecrawl로 수집한 소개글), `sections`(아래 7개)

| 섹션 | 주요 키 | 의미 / 화면 활용 |
|---|---|---|
| 사주명식 | `_기본명식._세차/_월건/_일진/_시진` | 년·월·일·시 기둥. 각각 `_천간`, `_지지`(이름·한자·음양·오행·십성), `_지장간`, `_운성` → **사주 8글자 표** |
| 사주명식 | `_신살` | 기둥별 신살 |
| 오행십성 | `_오행[]` | `element.name`, `point`, `percent`, `description`(발달/과다/부족…) → **오행 차트** |
| 오행십성 | `_십성[]` | 십성 분포 |
| 신강신약 | `_득령/_득지/_득시/_득세`, `name` | 예: `"신강"` → 한 줄 성향 설명 |
| 용신 | `_용신들.억부용신[]` | 예: 수(水) → "나에게 필요한 기운" |
| 대운_연운_월운 | `_대운수`, `_대운[]`, `_연운[]`, `_월운[]` | **10년 운 타임라인**, 올해·이번 달 운 |
| 사주풀이 | `천간합, 지지육합, 지지삼합, 지지방합, 천간충, 지지충, 공망, 형` … | 글자 사이 관계 → 상세 풀이 |
| 길흉성 | `길흉.{기둥번호}.{0=천간/1=지지}` | 그 글자에 붙은 신살 이름 목록. 예: 천덕귀인, 도화살, 역마살 → **신살 카드**. 길/흉 구분은 데이터에 없어서 화면에서 이름으로 분류(…귀인·정록 등 = 길성, …살 = 살) |

> 기둥 번호: 0=년, 1=월, 2=일, 3=시 (확인됨: 샘플의 양인살·현침살 위치가 시주 甲午와 일치)
> 대운_연운_월운: 기본 응답은 **현재 대운의 10년 연운 + 올해 월운**. `?year=` 로 다른 해의 월운 조회 가능.
> 사주풀이 `list`: 관계에 해당하는 기둥 번호 배열.

## 주의할 점 (화면 만들며 확인)
- **오행·십성 비율에는 일간(나 자신)도 포함**된다. 일간은 항상 '비견'으로 세어지므로, 십성 그룹 순위를 낼 때는 그 몫(8글자 중 1 = 12.5%, 시간 모름이면 6글자 중 1)을 빼야 한다. → `interpret.js`의 `tenGodGroups`
- **시간 모름(hmUnsure)이어도 `_시진`이 임시값으로 들어온다.** 비율 계산에선 이미 빠져 있지만(6글자 기준), 명식표·길흉성(기둥 3)·사주풀이(list에 3 포함)는 화면에서 숨겨야 한다.
- 오행 `description`: `과다`(넘침) / `발달`(잘 갖춤) / `적정` / `부족`. '넘친다'는 표현은 `과다`에만 쓴다.
- **첫 대운이 시작되기 전(어린 나이)이면 `_연운`에 올해가 없다.** `_연운`은 첫 대운 10년부터 시작하고, `?year=`를 줘도 바뀌지 않음. → 서버가 올해 간지·십성을 직접 계산해 넣는다 (`forceteller.py`의 `fill_current_year`, 항목에 `"computed": true`). 계산 결과는 API 연운 600건과 대조해 모두 일치함.
- **오늘의 일진·12시진은 API에 없다.** 서버가 계산해 응답에 `today`로 붙인다 (`forceteller.py`의 `today_section`, 한국 시간 기준, 캐시하지 않음). 일주·시주 계산은 포스텔러 사주명식 50건과 대조해 모두 일치함.
